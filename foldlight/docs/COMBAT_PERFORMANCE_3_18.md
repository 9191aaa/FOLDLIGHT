# 深期敌群与六首领性能 · 3.18

2026-10-17，本机 Windows、Godot 4.6.3 原生调试引擎、OpenGL Compatibility、NVIDIA GeForce RTX 5070 Ti Laptop GPU。窗口 1280×720、逻辑画布 1920×1080；独立用户数据目录，未限制 FPS，测量期间没有其他 Godot 或 Android 模拟器并行运行。

已修复物理追帧期间反复重建敌人图形的问题，完整可见战斗复测的帧间隔中位数从约 138–143 ms 降至约 35–37 ms。全部绘制细节、敌人数量、原招式和真实 60 Hz 物理均保留；这三个持续满载场景仍只有约 27–29 FPS，**不承诺 60 FPS 或实体手机性能**。完整数字见 [COMBAT_PERFORMANCE_3_18.json](COMBAT_PERFORMANCE_3_18.json)。临时夹具及日志保存在 `build/test-runtime/performance-318/`，不会进入发行包。

## 优化后的完整战斗复测

与下文基线使用同一个夹具及相同配置，所有敌人正常可见、参与自动选敌、碰撞、攻击和伤害。修复只将物理步内同一对象的绘制请求合并到下一次显示帧；没有隐藏敌人、删招式、降低人数或改变物理频率。

| 场景 | 实际敌人 | 弹丸补充前最低 / 峰值 | 帧间隔中位数 | P95 | 实测时长 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 折叠三角洲，80 普通敌人 | 80 | 254 / 260 | 34.781 ms | 42.428 ms | 20.03 秒 |
| 倒悬航渠，6 首领 + 50 普通（含 2 毒怪） | 56 | 251 / 260 | 36.596 ms | 44.298 ms | 20.03 秒 |
| 日轮列岛，同上，自然弹幕、零注入 | 56 | 55 / 260 | 34.731 ms | 41.365 ms | 35.03 秒 |

三组采样分别为 533 / 506 / 985 帧；物理步骤为 1,206 / 1,201 / 2,105，与实际 60 Hz 一致。实际威胁仍为 92 / 135 / 135，绘制调用中位数为 4,556 / 4,368 / 3,750，纸雕细节未通过削减绘制数量换取性能。自然样本实际发出 3,746 枚敌弹、839 枚友弹、零注入；行刑者完成 18 段连续冲刺，六首领均保持第三阶段、强度 5，使用全部原有招式类型。两组首领样本毒雾峰值均为 6。所有日志无脚本错误。

优化前由于至少 360 显示帧的取样要求，样本持续 46–51 秒；优化后持续 20–35 秒。攻击总数不能直接跨样本比较，也不能把补弹夹具中因弹幕预算已满而未生成的攻击误称为删除了招式。自然样本专门保留了零人工补弹的验证。

显示帧追帧引起的严重恶化已消除，但持续高密度不死目标压力仍偏重。当前结果应表述为显著改善及保留上限，不应表述为高密度稳定 60 FPS。

## 完整可见战斗基线

三组使用扩展后的生产地图、真实共享敌人和首领，玩家静止无敌并持有六把 Lv.5 自动武器。普通敌人高生命以维持实际人数；首领保持第三阶段（快照 `phase=2`，从零计数）、强度 5，完整执行原招式、预警、召唤请求和行刑者连续冲刺。没有降低物理频率、碰撞精度或关闭敌人绘制。

初始化后冻结自动增援与任务计时，创建实际护送任务，继续运行围猎、反向区域、毒雾和地图视觉。满额场景中支援请求照常发生，出生正确受人口及威胁预算限制。两个满弹样本在每次显示帧后补足 260 枚真实敌弹；自然样本不注入任何弹丸。各组至少 360 个显示帧，排除前 31 帧；严重掉帧使实际采样耗时约 46–51 秒。

## 分段定位

仅在诊断夹具中关闭战斗节点自身的物理回调，由真实 `SceneTree.physics_frame` 按原顺序、原提前退出条件调用全部方法，物理频率仍为 60 Hz。20 秒样本排除前 2 秒，记录 1,020 个物理步骤；80 敌人与 260 弹目标保持。

| 物理步骤 | 中位数 | P95 | 累计脚本耗时占比 |
| --- | ---: | ---: | ---: |
| 弹丸移动与命中 | 1.513 ms | 1.758 ms | 57.6% |
| 敌人 AI 与移动 | 0.817 ms | 1.116 ms | 31.5% |
| 自动武器 | 0.013 ms | 0.769 ms | 4.5% |
| 地形 | 0.060 ms | 0.086 ms | 2.4% |
| 支援关联 | 0.012 ms | 0.401 ms | 1.9% |
| 整条脚本流程 | 2.589 ms | 3.372 ms | — |

该轮引擎物理监视值为 18.184 / 22.001 ms，显示帧仍为 139.213 / 153.155 ms。引擎监视值和脚本单次调用不是相同统计口径，不能直接相减得出某个模块的耗时。关键追加证据是实际绘制信号：后续 1,024 物理步触发 **81,920 次敌人绘制，恰好每步 80 次**；130 个显示帧平均重建敌人图形 630.15 次。显示帧追赶多个物理步时，重复绘制工作显著累积。

两个诊断消融均只发生在夹具，未作为发布修改：

- 清除敌人碰撞层及掩码后，碰撞对从约 73 降至 0，帧间隔仍为 99.694 / 136.792 ms；还改变了运动路径，不能据此删除真实碰撞。
- 隐藏敌人后，仍有 80 个活动物理对象及约 73 个碰撞对，帧间隔降至 16.612 / 19.352 ms。但自动选敌也检查可见性，友弹从 233 降至 6，因此这个结果含额外变量，不能当成保留全部玩法的优化成绩。

对应原始文件：`profile-stages.json`、`profile-draw-counts-before.json`、`profile-no-enemy-masks.json`、`profile-hidden-enemies.json`。据此只合并了物理步内重复的视觉重建，并以全部可见、正常选敌的原三组完整战斗复测。

追加绘制计数复核保留 80 个可见敌人、约 73 个碰撞对与真实 60 Hz。敌人绘制从每显示帧平均 630.15 次降至 **79.83 次**，即约每个敌人每次显示帧一次；20.03 秒仍执行 1,206 个物理步。该诊断脚本流程中位数 / P95 为 2.477 / 3.255 ms；引擎物理监视值为 4.092 / 4.953 ms。诊断附加了逐步计数、逐帧 HUD 刷新，因此最终性能表使用上方完整生产调度夹具，避免混用统计口径。原始输出为 `profile-optimized.json`。

## 手机布局与边界可读性

真实触控布局截图使用六个实际首领和 50 普通敌人。六条血条采用两列三行，避开摇杆、冲刺、收纳及主动技能；顶端任务仍为两行。先采集预告画面，再推进真实预告时钟，采集已经生效的围猎画面。最终快照确认同时处于毒潮关闭区、反向区内和围猎边界外；围猎 `state=active`，首次圈外扣血仍有 1.975 秒宽限。提示合并为两行，返回围猎圈的方向、距离与目标仍可见，红色围猎边界、紫色反向区、绿色毒雾可区分。

该视觉夹具使用无敌玩家及受击后回复首领生命，仅保证六条血条持续存在以检查布局；生命显示使用实际定义的合理数值，不采用性能夹具的巨大血量。它不构成安卓设备性能或手感验证。毒雾另有受控视觉样本验证虚线预告、实线生效边界和暖色敌弹／灰青友弹／淡金返光的区分。截图位于 `build/test-runtime/pressure-ui-318/` 与 `build/test-runtime/readability-318/quiet-projectiles.png`；最终运行日志均无错误。

## 范围与既有成长边界

原生 Windows 压力测试不能保证浏览器、实体安卓手机、长时发热或不同显卡性能。APK 仍需独立启动与交互检查。场景为高生命目标持续围攻压力，不代表整局平均帧率。

3.18 的收纳容量上限为 96；静铰最多 8 层，冲刺爆破最多 6 层，达到上限后不能继续领取无效同类强化。旧横风仍受自动射击间隔 0.16 秒和穿透 12 次的既有上限约束；动纸冲刺冷却倍率最低 0.25，移动增益可继续生效。本次没有把所有旧词条改成无限成长，不能据此宣称所有增益在任意高层数都具有同样的实际收益。
