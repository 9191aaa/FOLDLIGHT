# 战斗查询优化 · 3.16

本轮优化共用战斗组件，迷航、无尽、EXE、APK 与网页都使用同一套计算路径。没有按平台或实时帧率删除敌弹、跳过碰撞、缩短警告，也没有降低纸雕画面质量。

## 改动

- 地形建立 192 像素网格索引，弹丸只查询附近候选；最终仍使用原来精确的旋转矩形、圆形包含判定。候选保留场景顺序。地图替换、节点移除、重新配置尺寸及世界变换都会使缓存失效。
- 纯墙体、折射柱不再对所有敌人执行没有效果的地面区域检查；日纹、湿墨不再执行没有效果的敌人检查。刺纸伤害与潮流推动逻辑保留。
- 每次弹道固定步为敌人真实圆形碰撞体建立 160 像素网格，供整批友弹复用；仍以实际碰撞体的中心、半径、缩放和启用状态作最终命中判断。生成新敌人会刷新索引，直接调用碰撞函数也会重新建立索引。超过现有 22 像素弹丸半径契约时安全回退全量精确检查。
- 远处敌人的无奖回收接口独立于击杀事件。默认保护队长、任务实体、Boss 和迷航房间配额；无尽确认任务失败后可以明确回收过期队长。支援连线随回收刷新。
- 自爆怪自然引爆标记为 `self_detonation / grants_kill_credit=false`，玩家打掉则为 `damage / true`。清理和回收不发击杀事件，经验系统可据此避免伪击杀。

## 本机测量

环境为 Windows，Godot 4.6.3 原生调试引擎，OpenGL Compatibility，NVIDIA GeForce RTX 5070 Ti Laptop GPU / 580.88；窗口 1280×720，逻辑画布 1920×1080。完整数值见 [COMBAT_PERFORMANCE_3_16.json](COMBAT_PERFORMANCE_3_16.json)。

控制对照使用相同生产场景、同一 36 个不死敌人、静止无敌玩家。每个渲染帧补齐 260 枚真实敌弹，飞行、碰撞、敌人攻击及引擎固定步照常执行；碰撞发生后数量可以暂时低于 260，本次两组补齐前最低均为 204。每组 240 个渲染帧，舍弃前 31 帧，取 209 个样本；前台窗口，无其他 Godot 测试同时运行。

基线仅恢复 3.15 提交 `ab22c0f463e8434b3d05e14ab0b27a8f3fe69ebf` 的五个原弹道/地形查询方法及旧地形枚举，画面、场景和敌人预算一致。这是查询实现对照，不是两个完整发行版的逐局比较。

| 同一 36 敌 / 260 弹压力夹具 | 旧查询 | 新查询 |
| --- | ---: | ---: |
| 渲染帧间隔中位数 | 50.824 ms | 18.763 ms |
| 渲染帧间隔 P95 | 65.741 ms | 27.456 ms |
| 240 渲染帧内物理步数 | 802 | 303 |
| 绘制调用数中位数 | 2463 | 2446 |

降低每个固定步的查询成本，也减轻了积压物理步的追帧放大。未更改物理频率、最大追帧数、碰撞规则或渲染更新方式。18.8 ms 的中位数约合 53 FPS，不能描述成锁定 60 FPS。

另一组沿用 3.14 的 **84 个不死敌人集中围攻、约 260 弹** 极端夹具。独立固定步探针中，弹道处理中位数由 3.988 降至 1.379 ms，地形效果由 1.212 降至 0.078 ms；常规引擎循环的渲染帧中位数仍由 182.188 仅降至 152.511 ms，依然严重卡顿。该结果支持减少重复查询，不能证明任意数量敌人的性能达标；新版无尽还需使用实际人口/威胁预算及分批出场。

这些是本机原生调试引擎、人工压力夹具的数据。没有据此声称实体手机、长时间发热场景或所有浏览器的帧率达标。Godot 进程/物理监视器的旧样本可能跨场景滞留，因此报告以墙钟帧间隔和独立组件探针为主要依据。

## 正确性回归

新增 `test_combat_spatial_queries_3_16.gd` 覆盖：数千采样点对照旋转墙/圆柱全扫描、格子边界、地形移动/缩放配置/移除失效、真实命中边缘与近距离未命中、禁用碰撞体、移动敌人、超规格弹丸回退、无奖回收及自爆击杀归因。

同时复验地形战斗、自动武器阵列、弹道准确性、返光寻路/接力、自爆怪、任务返光、场景临时节点清理与地面提示。测试保留真实场景和碰撞，不以索引内部数据结构代替玩法断言。
